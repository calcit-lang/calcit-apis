# Upgrade calcit-apis to Calcit 0.13.77

- Raise the compiler baseline from 0.13.32 to 0.13.77 and pin the JavaScript runtime package to the exact matching version.
- Install Calcit modules strictly and JavaScript packages immutably before verifying compiler/runtime alignment.
- Pin the maintained setup action and restrict the workflow token to read-only repository contents.
- Preserve generated API/LLM data, application version 0.0.2, site behavior, and push-only deployment.
- Use the final compatible Calcit 0.13.51 formatter and structural schema editor to normalize Snapshot namespace/definition keys and declare `app.schema/slurp-cirru-code` as an explicit filesystem-reading macro before retrying 0.13.77.

## Blocked validation

- Yarn 4.12.0 installation and its immutable repeat pass, and compiler plus `@calcit/procs` verify as exact 0.13.77.
- Strict Caps rejects the existing Respo dependency graph because root and transitive constraints select different reel, markdown, UI, and Respo core versions.
- A non-strict diagnostic install reaches the project Snapshot, but 0.13.77 then rejects the published `lilac@0.5.5` dependency at `lilac.core/deflilac` for its legacy whole-Dynamic macro schema.
- Lilac compatibility and release follow-through are tracked by Calcit issues #682 and #679; the Respo compiler compatibility patch is still awaiting a consumable release under #670. Do not add downstream workarounds.

## 阻塞验证

- Yarn 4.12.0 安装与 immutable 重复安装均通过，编译器和 `@calcit/procs` 也精确对齐到 0.13.77。
- Strict Caps 因现有 Respo 依赖图中 root 与传递约束选择不同的 reel、markdown、UI 和 Respo core 版本而拒绝继续。
- 非 strict 诊断安装可以进入项目 Snapshot，但 0.13.77 随后会在已发布的 `lilac@0.5.5` 中拒绝 `lilac.core/deflilac` 的 legacy whole-Dynamic macro schema。
- Lilac 兼容性与发布收尾由 Calcit issues #682/#679 跟踪；Respo 修复仍在 #670 等待可消费 release。当前仓库不得加入下游规避。
